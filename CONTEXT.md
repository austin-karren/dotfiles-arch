# Rice

The configuration of one desktop: CachyOS running Omarchy on Hyprland. This
glossary exists because the vocabulary here is genuinely ambiguous — Omarchy,
Hyprland, Walker and this repo all use words like "theme", "menu" and "toggle"
to mean different things, and three of the menus are one keystroke apart.

## Layers

**Omarchy**:
The upstream desktop layer installed at `~/.local/share/omarchy`, managed by its
own git checkout and updated with `omarchy update`. Read-only to us.
_Avoid_: the distro, upstream

**Rice**:
The set of deliberate deviations from a stock Omarchy install — everything this
repo tracks, plus the helper scripts in `~/.local/bin`.
_Avoid_: dotfiles (that is the repo), config

**Machine-side**:
A config file that stays on the machine and is deliberately never tracked,
because it is generated by Omarchy or carries personal identity.
_Avoid_: local, untracked, ignored

**Identity file**:
A machine-side file holding a name or email address, included by a tracked file
that itself contains no identity. `~/.gitconfig.local` is the reference example.
_Avoid_: secrets file, private config

## Appearance

**Theme**:
Omarchy's unit of appearance — a directory of per-application colour files.
Stock themes live under Omarchy; ours live in `~/.config/omarchy/themes`.
_Avoid_: colorscheme, palette (a palette is an input to a theme, not a theme)

**Appearance**:
Whether the desktop is light or dark. Not independent state: it is a property of
the active Theme, flagged by a `light.mode` marker file inside it.
_Avoid_: mode, dark mode setting

**Pinned wallpaper**:
A wallpaper that outranks whatever the active Theme ships, so it survives theme
changes. Copied out of any theme directory so it cannot be deleted underneath us.
_Avoid_: background, default wallpaper

**Palette** (Aether sense):
Sixteen colours extracted from an image, before any theme files are rendered from
them. An input to a generated Theme.
_Avoid_: theme, colorscheme

## The four menus

These are the terms most worth being strict about. All four are reachable within
one modifier of each other, and two of them are named "toggle".

**Launcher**:
Walker in its default provider mode, `ALT+SPACE`. Searches applications. The
thing you type into when you know what you want.
_Avoid_: walker, app menu, spotlight

**System Palette**:
Our own browse-first list of system commands, `SUPER+SPACE`, backed by
`~/.local/bin/quick-menu`. Exists for discovery — skimming to find out that a
command exists at all.
_Avoid_: quick menu, command palette, raycast

**Omarchy Menu**:
Omarchy's own root menu, `SUPER+CTRL+SPACE`. The full nested tree of everything
Omarchy can do.
_Avoid_: the menu, main menu

**Toggle Menu**:
One submenu of the Omarchy Menu, reachable directly at `SUPER+CTRL+O`. Holds the
on/off switches: Screensaver, Nightlight, Idle, Notifications, Bar, Layout,
Ratio, Gaps.
_Avoid_: options menu, settings, toggles

**Ratio**:
The Toggle Menu entry that constrains a lone window to a 1:1 aspect ratio, by
adding or removing Hyprland's `single_window_aspect_ratio` setting.
_Avoid_: single window mode, square mode, 1 window ratio

## Waybar behaviour

**Second-click dismissal**:
Clicking a bar module opens its window; clicking the same module again dismisses
it. Two separate single clicks, each a complete open-or-dismiss decision — not a
double-click gesture, which Waybar reports as its own distinct event.
_Avoid_: double click, click toggle

**Toggle wrapper**:
A script standing between a bar module and the command it launches, added solely
to give that module Second-click dismissal. `window-toggle`, `menu-toggle` and
`calendar-toggle` are the three we have.
_Avoid_: handler, launcher script

**Dismiss**:
To make a window go away, without specifying whether it was closed or merely
hidden — a distinction each Toggle wrapper decides for itself based on how
expensive the window is to restart.
_Avoid_: close, hide, kill (each of those asserts a mechanism)

## Launcher internals

**Walker**:
The launcher front-end. Owns the window, the theme and the list widget.
_Avoid_: elephant, dmenu

**Elephant**:
Walker's backend. Owns the entries, the search scoring and the usage history.
Anything about *what appears* in a list is Elephant's, not Walker's.
_Avoid_: walker, backend

**Provider**:
One Elephant source of entries — `desktopapplications`, `websearch`, `menus:*`,
`clipboard`, `symbols`, `calc`. A Launcher list is a set of Providers.
_Avoid_: source, plugin, mode

**Frecency**:
Elephant's ranking of entries by combined frequency and recency of activation.
Off by default here.
_Avoid_: most used, history, MRU

**Favorite**:
An entry the user has explicitly pinned to the top of a list, independent of
usage. Aspirational: Elephant has no pin primitive, so nothing in the rice
implements this today.
_Avoid_: pinned (that word is taken by wallpapers), starred, bookmark
